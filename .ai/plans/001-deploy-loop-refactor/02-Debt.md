## 2. North-Star Target: Label-based Dynamic Proxy

### Как это работает

Проект декларирует маршрутизацию через Docker labels в `docker-compose.yml`:

```yaml
services:
  app:
    image: ghcr.io/myorg/myapp:latest
    labels:
      traefik.enable: "true"
      traefik.http.routers.myapp.rule: "Host(`myapp.example.com`)"
      traefik.http.services.myapp.loadbalancer.server.port: "80"
      traefik.http.routers.myapp.entrypoints: "websecure"
      traefik.http.routers.myapp.tls.certresolver: "letsencrypt"
    networks:
      - proxy-net
    env_file:
      - .env.platform

networks:
  proxy-net:
    external: true
```

Reverse-proxy (Traefik) подключается к Docker socket и:

```
▶ Watch Docker events (container start/stop)
  ├── container с label traefik.enable=true → авто-генерация router + service
  ├── container label traefik.http.routers.X.rule=Host(...) → route rule
  ├── container label traefik.http.services.X.loadbalancer.server.port → upstream port
  └── container stop → авто-удаление router + service (zero stale config)

▶ Watch Docker events (container crash/restart)
  └── upstream IP changes → автоматически (Docker resolver → service IP)

▶ Let's Encrypt (ACME) — built-in (TLS-ALPN-01 challenge):
  └── acme.sh удаляется → certbot/Traefik ACME управляет lifecycle
```

### Преимущества

| Аспект | Текущая (nginx + vhost) | North-star (Traefik) |
|--------|------------------------|---------------------|
| **Upstream resolution** | `set $upstream_X` + `resolver 127.0.0.11` | Авто через Docker API (контейнер name → IP) |
| **Add project** | scaffold → add-vhost.sh → nginx -s reload | docker compose up (labels → авто-route) |
| **Remove project** | remove-vhost.sh → nginx -s reload | docker compose down (Docker event → авто-remove) |
| **SSL provisioning** | acme.sh + cron + overlay cert path | Built-in Let's Encrypt (ACME) |
| **Platform vhosts** | envsubst templates (6 files, отдельный механизм) | Traefik dynamic config file или labels на infra-сервисах |
| **Config surface** | nginx.conf + 6 templates + N overlay .conf + module.yaml | labels в docker-compose.yml + traefik.yml |
| **Restart ordering** | nginx стартует до upstream (ленивый DNS спасает) | Нет зависимости — Upstream resolved at request time |
| **Reload** | docker compose exec nginx nginx -s reload (hook) | Zero — Docker events real-time |

### Недостатки / Риски

| Риск | Описание | Mitigation |
|------|----------|------------|
| **Vendor lock-in** | Привязка к экосистеме Traefik labels — миграция на другой proxy = изменение labels во всех проектах | Прокси-абстракция через middleware layer — labels = бизнес-конфигурация, не implementation detail |
| **Docker socket exposure** | Traefik требует `docker.sock` — если скомпрометирован proxy, злоумышленник получает полный доступ к Docker | Read-only socket mount (`:ro`), use `--providers.docker.constraints` filter |
| **Big-bang migration** | Все проекты одновременно должны иметь корректные labels — staged rollout невозможен без dual-stack | Dual-stack: nginx + Traefik параллельно, поэтапный перевод проектов |
| **Feature parity** | nginx auth_request (авторизация), custom error pages, sub_filter | Traefik Middleware (ForwardAuth, etc.) — проверить покрытие |
| **Docker version** | Требуется Docker Engine API ≥ 1.25 (labels support) | Все современные версии Docker поддерживают |

### ## @rationale: Traefik vs nginx-proxy (docker-gen)

**Q:** Почему Traefik, а не nginx-proxy (jwilder/docker-gen)?
**A:** Traefik имеет built-in Let's Encrypt, middleware pipeline (auth, rate limiting, headers), и единый binary без внешних генераторов шаблонов. nginx-proxy требует nginx + docker-gen + template + acme-companion — 4 контейнера вместо 1. Traefik также имеет dynamic config через файловый провайдер (для платформенных vhost), что покрывает use case envsubst-templates.

## 3. Rationale: Why Deferred (Big-Bang vs Incremental)

### ## @rationale: Incremental (Option A+D) chosen over big-bang (Option C)

**Q:** Почему не выбран Option C сейчас?
**A:** Три причины:

1. **Business continuity.** Замена proxy — big-bang операция с даунтаймом. Платформа уже в production (tronyx-vps). Миграция nginx → Traefik требует одновременного переключения всех vhost. incremental fix (Option A+D) не требует даунтайма.
2. **Resource constraints.** Option C требует: design-review Traefik middleware coverage, dual-stack rollout plan, тестирование совместимости с observability-net (grafana, loki, prometheus), перенос SSL provisioning с acme.sh на Traefik ACME. Это 2-3 дня работы, которые сейчас направлены на закрытие fire (сессии деплоя).
3. **Unknown unknowns.** Traefik в Docker Compose stack с include-секциями, profiles и платформенными сервисами (Hermes, Langfuse, Grafana, Loki) — не тестировался. Миграция вскроет несовместимости, которые потребуют дополнительных итераций.

**Trade-off:** Option A+D фиксирует симптомы за 7 задач (дней). Option C требует больше времени сейчас, но убивает весь класс upstream/resolver/reload/ordering проблем навсегда.

## 7. Design Decisions

### ## @rationale: Traefik over nginx-proxy (docker-gen)

**Q:** Почему Traefik, а не nginx-proxy (jwilder/nginx-proxy)?
**A:** Traefik имеет built-in Let's Encrypt, middleware pipeline, и single binary без внешних генераторов шаблонов. nginx-proxy требует nginx + docker-gen + template + acme-companion — 4 контейнера вместо 1. Traefik dynamic config через файловый провайдер покрывает use case платформенных vhost (сейчас 6 .conf.template файлов).

### ## @rationale: Dual-stack migration over big-bang cut-over

**Q:** Почему parallel (nginx + Traefik) а не single-step switch?
**A:** Production continuity. Dual-stack позволяет мигрировать сервисы по одному (Phase 2 → Phase 3) и откатываться на nginx при проблемах. Single-step безопасен только для staging-ноды.

### ## @rationale: File-based dynamic config for platform vhosts

**Q:** Почему не через Consul/etcd для platform services?
**A:** File-based dynamic config (traefik.yml dynamic_conf) проще — не требует дополнительных инфра-сервисов, консистентен с текущей моделью (git push → SCP файлы на VPS). Consul/etcd — overengineering для 6 платформенных сервисов.
