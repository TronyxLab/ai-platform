# 028 Deploy Postmortem — почему 10 циклов не дали воспроизводимый clean deploy

Период анализа: 2026-08-25 → 2026-09-02 · 154 non-merge коммита (~90 fix-класса) · 7 холодных bootstrap-попыток на пересоздаваемых VPS + 2 фазы CI-канала · ~30 запусков bootstrap-node · журнал прогонов: 530 падений из 1533 (324 после 08-25).

**Агрегация:** ~90 fix-коммитов → ~50 уникальных находок (F-001..F-037 в 011; F-01..F-22 в 014/017/018; F-01..F-14 в 020/022/027) → **6 системных причин**. Количество багфиксов ≠ количество проблем: класс повторялся на новом пути исполнения вместо устранения контракта.

---

## VERDICT

**Current state:**
- Критерий владельца «голая нода → ОДНА команда → стек + все проекты» **выполнен один раз, вручную** — 027 acceptance-validation, 2026-09-02, tronyx-vps: `make bootstrap-node` rc=0, 3 проекта live, повторный bootstrap no-op 66s, фазы A–H PASS, context-promote SUCCESS, CI main зелёный впервые с 2026-08-17.
- Достигнуто **после 14 новых находок (4×P0), найденных на чистой ноде в тот же день** — седьмая холодная попытка за неделю, каждая предыдущая находила 2–14 новых проблем.
- **Воспроизводимость не закреплена ничем**: полный cold-start не покрыт ни одним автоматическим контуром — deploy-arena спроектирована (план 026), но не построена (`~/projects/deploy-arena/` отсутствует); `make test-node` ручной и в 027 BLOCKED (test-VPS недоступна); ни один из 8 CI-workflows не бутстрапит чистую машину; branch protection/required-check на push-путь отсутствует (platform-test был красен с 2026-08-17 по 09-02 — промоуты продолжались).
- Путь по коду сегодня проходим, но это «подтверждено одним ручным прогоном», а не «гарантировано системой». Состояние = разово доказанный, не защищённый от регрессии результат.

**Main root causes:**
1. **Нет повторяемого автоматического теста clean-server** — ручная холодная валидация была единственным детектором cold-only багов; цикл обратной связи = дни, поэтому каждый прогон = экспедиция с новыми находками.
2. **Разрыв честности статусов**: silent-успех при rc=0 в ≥5 компонентах (vhost rendered=0, restore «чёрная дыра» над пустым кластером, nightly-бэкапы не работали месяц, gitleaks abort за 0.3s, ssl «provisioned» всегда) — ложные зелёные маскировали корневые причины и доминировали стоимость диагностики.
3. **Ветки «если уже существует»**: ~6 из 14 находок 027 — поведение чистой ноды ≠ прогретой (stub ai-platform.yaml, маркеры, absent-модули, done-skip без перепроверки), а идемпотентность фаз не имеет обязательного теста.
4. **Транспорт секретов/AGE/env**: каноническая форма ключа и env-приоритеты не верифицируются; fail-loud семантика дофикшивалась 3 раза (source=sops → module-aware → systemd auto-detect), каждый фикс создавал следующий путь отказа.
5. **CI-канал верифицируется только живым прогоном**: каждый подкласс CI-багов повторился ровно дважды (пины ×3, fetch-depth ×2, job-level env ×2 со взаимным откатом), один прогон D5 убили подряд 3 P0.
6. **Внешние предпосылки вне контрактов**: DNS A-записи, форма AGE-ключа на машине оператора, sops-секреты, SSH-ключи, deploy-key overlay, локальные исходники проектов — ничто из этого не проверяется префлайтом; внешние блокеры (billing, S3-креды, пересоздание нод посреди валидации) трижды маскировались под незавершённость продукта.

**P0 blockers:**
1. Минимальный срез deploy-arena (план 026): автоматический cold-bootstrap на чистой VM + обязательный идемпотентный re-run — превращает «одна команда работает» из ручного утверждения в повторяемый тест.
2. Required-check на push в main (platform-test): без блокирующего красного CI регрессии живут неделями и попадают в промоуты.
3. Pre-flight верб (validate-node-input): проверка входного контракта (форма AGE-ключа, наличие sops-файлов, DNS-разрешимость, SSH-ключи, node-configs) до SCP-фазы — fail-loud на старте вместо exit 10 на φ4/φ8.

**Minimal path to DONE:**
1. `arena up/verify/down` single-node headless: cold-bootstrap rc=0 → проекты healthy → re-run no-op → reboot-проба. (T1–T9 срез плана 026, без cloud/M2.)
2. Включить тот же срез в CI как required-check (или scheduled nightly) — каждое изменение bootstrap-контура гоняется на чистой VM.
3. Pre-flight верб + final-verify фаза в конце bootstrap: end-state assertions (серты на диске, образы спулены, проекты healthy/vhosted, secrets.env полный) до exit 0.
4. Закрыть класс honesty: post-condition проверки для 5 исторических silent-точек уже внесены — добавить их в чек-сьют как гейты, чтобы дрейф ловился.
5. Env-hermeticity guard для тестов (NODE_NAME-класс утечек) + required-check устранит «ложно-зелёный» класс навсегда.

Критерий DONE — см. §Acceptance в minimal-fix-plan.md.

## Разбор полётов: почему десять циклов не сошлись

1. **Цикл обратной связи был длиной в день и стоил часа ручной работы** — cold-only баги не могли быть пойманы ничем, кроме очередного холодного прогона (RC1). Отсюда «десяток циклов» = 7 экспедиций, а не 10 итераций теста.
2. Ложные зелёные (RC2) превращали «PASS» в «новая ошибка через фазу» — диагностика (φ4 AGE: 5 диагностических коммитов на одну проблему) съедала сессии.
3. Классы фиксировались **по пути исполнения, а не по контракту**: secrets ×3 пути, NODE_NAME ×4 места, shallow ×2, job-env ×2 — следующий путь того же класса находился на следующей ноде.
4. Идемпотентность и «чистая нода» не имели ни одного обязательного теста — обе подтверждались только дриллами вручную.
5. Красный CI не блокировал ничего 2.5 недели — регрессии свободно доезжали до промоутов.
6. **Система не «плохая»**: к 09-02 классы падения сместились с «стек не поднимается» на P2/P3-гигиену (F-11..F-14), фазовая машина, strict-init и fail-loud контракты сошлись. Сегодня осталось **2–3 P0-действия (закрепить, а не дописать)**, после которых критерий становится воспроизводимым свойством, а не вчерашним достижением.
