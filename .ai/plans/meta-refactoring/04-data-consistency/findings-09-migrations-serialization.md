## DATA-901: NodeYaml._write_back — «сохранение комментариев» иллюзорно, все мутации node.yaml стирают комментарии
- **Severity:** HIGH · **Confidence:** HIGH
- **Files:** core/internal/shared/node_yaml/_core.py · **Symbols:** `NodeYamlCore._load` (:97), `yaml.safe_load` (:114), `_write_back` (:325), ruamel-ветка (:347–357), PyYAML-fallback (:363); callers `projects.py:240,272,324` (add/remove/update_project), context_registry→add_context · **Invariant:** round-trip node.yaml должен сохранять документацию оператора (комментарии)
- **Violating scenario:** START: node.yaml с комментариями оператора → операция `add_project`/`remove_project`/`add_context` на ноде → END: файл переписан БЕЗ единого комментария, лог пишет «comments preserved». Корень: load идёт через `yaml.safe_load` → plain dict; ruamel-дамп plain dict не восстанавливает комментарии (нужен ruamel-round-trip-load), а при отсутствии ruamel (НЕ запинен в pyproject.toml/requirements.txt — grep пуст) молча используется PyYAML.
- **Evidence:** `_load`: `raw = cast(object, yaml.safe_load(f))`; `_write_back` docstring «Uses ruamel.yaml first for comment preservation» + log IMP:9 «comments preserved» — утверждение не соответствует механике. · **Impact:** потеря operator-документации в node.yaml на каждой проектной операции; шумные diff'ы и merge-конфликты в контекстных репозиториях; TRAP[BUG]-история в файле показывает, что fallback-ветка уже ловили как P2, но root-причина (safe_load) не устранена. · **Minimal fix:** грузить через `ruamel.yaml.YAML()` round-trip (`load=f`) и дампить тот же объект; ruamel добавить в зависимости; ImportError → warning, а не тихий fallback. · **Required test:** запись node.yaml с комментариями → add_project → assert комментарии сохранены (сейчас RED). · **Phase:** serialization-fix

## DATA-902: persist_project_key — неатомарная запись хранилища LLM-ключей + silent-reset загрузчика = полная потеря ключей
- **Severity:** CRITICAL · **Confidence:** HIGH
- **Files:** core/internal/llm/key_provisioner.py · **Symbols:** `persist_project_key` — load :366–378, write :391–396 (`open("w")` :392, `json.dump(store,...)` :393, `chmod(0o600)` :396), `json.load` :371 · **Invariant:** state-файл секретов должен писаться атомарно (tmp+fsync+replace, канон atomic_writer.atomic_write_json) и не терять записи при сбое
- **Violating scenario:** START: store.json с N виртуальными ключами проектов → операция provision ключа N+1, процесс убит/OOM/питание посреди `json.dump` (нет tmp+replace, нет fsync) → END: усечённый JSON; СЛЕДУЮЩИЙ вызов: `except json.JSONDecodeError → store = {}` (warning IMP:6) → дамп перезаписывает файл стором из одного ключа — все N ключей молча утрачены. ## DATA-905: decrypt_secrets пишет secrets.env через os.fdopen("w") без encoding — locale-dependent на ноде
- **Severity:** MEDIUM · **Confidence:** MEDIUM
- **Files:** core/internal/secrets/decrypt_secrets.py:326 · **Symbols:** `_plw_body_write_secrets_env` (`os.fdopen(tmp_fd, "w")`) · **Invariant:** текстовые конфиги пишутся в UTF-8 явно независимо от LC_ALL ноды
