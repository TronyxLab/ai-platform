# VHOST_CONTRACT — nginx vhost generation

---

## 1. Контракт генерации vhost'ов

### 1.1 Naming: nginx-переменные

**Правило:** переменные — только `[a-zA-Z0-9_]`; дефисы имени проекта заменяются underscore
(`nginx_safe_name="${project_name//-/_}"` в `generate_vhost_body()` — для upstream-переменных;
`project_name` остаётся для `server_name`/`ssl_certificate`/имени файла).

### 1.2 Resolver directive

**Правило:** каждый server block содержит `resolver 127.0.0.11 valid=30s ipv6=off;`
(встроенный DNS Docker; TTL 30s; IPv4-only сеть).

### 1.3 proxy_pass через переменную

**Правило:** `proxy_pass` всегда через переменную (`set $upstream_my_app http://my-app:8080;`),
никогда статический hostname — nginx кэширует IP при старте → 502/503 после рестарта контейнера
с новым IP; переменная форсирует runtime resolution через resolver.

### 1.4 Let's Encrypt cert paths

**Правило:** сертификаты — только Let's Encrypt `/etc/letsencrypt/live/<domain>/`
(wildcard для поддоменов PLATFORM_DOMAIN, personal для внешних); self-signed default.crt
в production vhost запрещён; dev — отдельный `ssl-dev.conf`.

### 1.5 GENERATED-маркер

**Правило:** вторая строка vhost — `# GENERATED by add-vhost.sh — DO NOT EDIT`; файлы без
маркера считаются ручными (не удаляются render-all при очистке stale). Детекция:
`grep -q "GENERATED by add-vhost.sh"` (grep без head — надёжнее, позиция-независимо).

### 1.6 HTTP/2 отдельной директивой

**Правило:** `http2 on;` отдельной директивой (не `listen ... http2` — синтаксис deprecated
в nginx ≥1.25.1).

## 2. Контракт с add-vhost.sh

| Требование | Проверка | Команда |
|---|---|---|
| Синтаксическая валидация | Каждый сгенерированный vhost проходит `nginx -t` | `nginx -t -c /etc/nginx/nginx.conf` |
| Нормализация дефисов | `$upstream_my_cool_app` для проекта `my-cool-app` | `grep 'upstream.*my-cool-app'` → пусто |
| GENERATED-маркер | Вторая строка содержит маркер | `head -2 | grep "GENERATED"` |
| Cert paths | Только Let's Encrypt пути | `grep 'ssl_certificate' | grep 'letsencrypt'` |
| Resolver | `resolver 127.0.0.11` присутствует | `grep 'resolver'` |
| proxy_pass через переменную | Нет `proxy_pass http://` (статический hostname) | `grep 'proxy_pass http://'` → пусто |

## 3. Gate тест

**Файл:** `tests/gates/test_gate_vhost_nginx_t.py` (маркер: `@pytest.mark.gate`)

**Алгоритм:**
1. Создать эталонный `node.yaml` с проектами, содержащими дефисы в имени + поддомены PLATFORM_DOMAIN
2. Вызвать `add-vhost.sh --render-all --node-yaml <path> --output-dir <tmp_path>`
3. Создать минимальный `nginx.conf` (events + http + resolver + include)
4. `docker run --rm -v <overlay_dir>:/etc/nginx/conf.d:ro nginx:alpine nginx -t`
5. Assert exit code 0

**Edge cases:**
- Docker недоступен → skip (не fail)
- `my-cool-app` → nginx -t PASS (проверка нормализации дефисов)
- `independent.com` → personal cert path (не wildcard)

## 4. Common pitfalls

### ⚠️ TRAP[BUG] · — · Дефисы в upstream именах: `$upstream_my-cool-app` → nginx syntax error
· Fix: нормализация `nginx_safe_name="${project_name//-/_}"` · Prevention: все upstream-переменные
через `nginx_safe_name` · Rev: — (синтаксис nginx неизменен)

### Детекция GENERATED-маркера — grep без head: `generated_header()` выводит 2 строки,
`head -1` читает только первую → маркер пропускается; канон — `grep -q "GENERATED by ..."`

### ⚠️ TRAP[DECISION] · 2026-07-20 · — · proxy_pass через переменную
**· Rejected:** Статический hostname в `proxy_pass http://app:8080`
**· Reason:** Статический hostname кэшируется при старте nginx; при перезапуске контейнера (новый IP) — 502/503
**· Rev:** Если nginx перейдёт на динамическую резолюцию через `zone` directive — пересмотреть

## 5. Эталонные конфиги

- `core/modules/nginx/config/` — production vhost конфиги (платформенные модули: grafana, loki, prometheus, langfuse, hermes-dashboard)
- `core/modules/nginx/dev-config/` — dev-окружение (self-signed + локальные домены)
- `core/modules/nginx/overlays/` — сгенерированные vhost'ы проектов (через `add-vhost.sh --render-all`)

Каждый эталонный конфиг сам должен следовать VHOST_CONTRACT (GENERATED-маркер не обязателен — это ручные файлы).

### Dev-часть модуля (официальное исключение канона)

nginx — единственный модуль с локальной dev-инфраструктурой вне шаблона
«Структура модуля» (core/modules/AGENTS.md). Вынос в core/internal/nginx-dev/ отвергнут —
режет модуль ради эстетики; исключение документировано здесь.

| Элемент | Назначение | Кто использует |
|---------|-----------|----------------|
| `dev-config/` | dev nginx конфиги (self-signed + локальные домены) | docker-compose.dev.yml |
| `dev-certs/` | сгенерированные dev-сертификаты (gitignored) | dev_cert_generator.py |
| `dev_cert_generator.py` | генерация dev SSL-сертификатов (`make dev-certs`, CERT_BACKEND=auto/mkcert/openssl) | helpers.mk dev-certs |
| `docker-compose.dev.yml` | dev-стек nginx (localhost-порты) | разработчик (docker compose -f ... up) |
| `error-pages/` | кастомные error-страницы (403/404/502/503) | production nginx (volume-mount) |
| nginx_reload_hook.sh | reload-хук после рендера vhost'ов (модуль-локальный — backticks сняты: doc-header резолвер работает от корня репо) | add-vhost.sh / render-vhosts |
| `overlays/` | сгенерированные vhost'ы проектов (GENERATED by add-vhost.sh) | production nginx |

Правило для агентов: dev-файлы НЕ трогаются деплой-путями (bootstrap доставляет
модуль целиком, но dev-элементы используются только на dev-машине); канонический
путь деплоя — module.yaml + docker-compose.base.yml + config/.

## 6. Template Syntax Contract

`.template` файлы в nginx-модуле — только в `config/`:

| Директория | Синтаксис | Рендерер | Когда применяется |
|-----------|-----------|----------|-------------------|
| `config/*.conf.template` | `${PLATFORM_DOMAIN}` | nginx Docker entrypoint (container-internal envsubst script) | При старте nginx-контейнера |

**Правило:** Никогда не смешивать `${}` и `{{}}` в одном файле.

**CI gate:** `test_gate_nginx_template_syntax.py` проверяет, что:
- Файлы в `config/` НЕ содержат `{{`
- Исключение: nginx-переменные вида `${host}`, `${request_uri}` в `config/` разрешены
