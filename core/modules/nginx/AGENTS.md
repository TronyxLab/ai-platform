---

## 1. Контракт генерации vhost'ов

### 1.1 Naming: nginx-переменные

**Правило:** Все nginx-переменные используют только `[a-zA-Z0-9_]`. Дефисы в имени проекта (`my-cool-app`) заменяются на underscore:

```nginx
# ✅ CORRECT:
set $upstream_my_cool_app http://my-cool-app:8080;
proxy_pass $upstream_my_cool_app;

# ❌ WRONG (syntax error — nginx парсит $upstream_my минус cool минус app):
set $upstream_my-cool-app http://my-cool-app:8080;
```

**Реализация:** В `generate_vhost_body()` создаётся локальная переменная:
```bash
local nginx_safe_name="${project_name//-/_}"
```
`nginx_safe_name` используется для upstream-переменных, `project_name` — для `server_name`, `ssl_certificate` и имени файла (там дефисы допустимы).

### 1.2 Resolver directive

**Правило:** Каждый server block содержит resolver-директиву для динамической резолюции upstream'ов:

```nginx
resolver 127.0.0.11 valid=30s ipv6=off;
```

- `127.0.0.11` — встроенный DNS Docker (соответствует `nameserver 127.0.0.11` в `/etc/resolv.conf` контейнера)
- `valid=30s` — TTL кэширования DNS
- `ipv6=off` — отключает AAAA-запросы (сеть проекта — IPv4-only)

### 1.3 proxy_pass через переменную

**Правило:** `proxy_pass` всегда использует переменную, никогда — статический hostname:

```nginx
# ✅ CORRECT (runtime resolution через resolver):
set $upstream_my_app http://my-app:8080;
proxy_pass $upstream_my_app;

# ❌ WRONG (nginx резолвит hostname один раз при старте/ reload):
proxy_pass http://my-app:8080;
```

**Причина:** Статический hostname в `proxy_pass` резолвится nginx при старте (или reload). Если контейнер перезапускается с новым IP (Docker network), nginx продолжает использовать кэшированный IP → 502/503. Переменная форсирует runtime resolution через resolver.

### 1.4 Let's Encrypt cert paths

**Правило:** Сертификаты — Let's Encrypt, не self-signed default.crt:

```nginx
# ✅ CORRECT (Let's Encrypt):
ssl_certificate     /etc/letsencrypt/live/app.tronyx.ru/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/app.tronyx.ru/privkey.pem;

# ❌ WRONG (self-signed — не должен появляться в production vhost):
ssl_certificate     /etc/ssl/default.crt;
ssl_certificate_key /etc/ssl/default.key;
```

- Для поддоменов PLATFORM_DOMAIN: wildcard cert `/etc/letsencrypt/live/*.tronyx.ru/`
- Для внешних доменов: personal cert `/etc/letsencrypt/live/<domain>/`
- Dev-окружение — отдельный `ssl-dev.conf`, не production vhost

### 1.5 GENERATED-маркер

**Правило:** Вторая строка каждого сгенерированного vhost содержит маркер:

```nginx
# ============================================================
# GENERATED by add-vhost.sh — DO NOT EDIT
# ============================================================
```

Маркер используется в `render_all()` для идентификации файлов, созданных `add-vhost.sh`. Файлы без маркера считаются ручными и НЕ удаляются при `render-all` с очисткой stale vhost'ов.

**Детекция:** `grep -q "GENERATED by add-vhost.sh" "$gen_file"` — не зависит от позиции маркера (не `head -1`).

### 1.6 HTTP/2 отдельной директивой

**Правило:** `http2 on;` указывается отдельной директивой, не через параметр `listen`:

```nginx
# ✅ CORRECT:
listen 443 ssl;
http2 on;

# ❌ WRONG (несовместимо со старыми версиями nginx:alpine):
listen 443 ssl http2;
```

**Причина:** `listen ... http2` — синтаксис nginx ≥1.25.1 (новый модуль). Отдельная `http2 on;` директива совместима со всеми версиями nginx:alpine и с upstream nginx native packages на VPS.

## 2. Контракт с add-vhost.sh

| Требование | Проверка | Команда |
|---|---|---|
| Синтаксическая валидация | Каждый сгенерированный vhost проходит `nginx -t` | `nginx -t -c /etc/nginx/nginx.conf` |
| Нормализация дефисов | `$upstream_my_cool_app` для проекта `my-cool-app` | `grep 'upstream.*my-cool-app'` → пусто |
| GENERATED-маркер | Вторая строка содержит маркер | `head -2 | grep "GENERATED"` |
| Cert paths | Только Let's Encrypt пути | `grep 'ssl_certificate' | grep 'letsencrypt'` |
| Resolver | `resolver 127.0.0.11` присутствует | `grep 'resolver'` |
| proxy_pass через переменную | Нет `proxy_pass http://` (статический hostname) | `grep 'proxy_pass http://'` → пусто |

## 3. Gate тест

**Файл:** `tests/gates/test_gate_vhost_nginx_t.py` (маркер: `@pytest.mark.gate`)

**Алгоритм:**
1. Создать эталонный `node.yaml` с проектами, содержащими дефисы в имени + поддомены PLATFORM_DOMAIN
2. Вызвать `add-vhost.sh --render-all --node-yaml <path> --output-dir <tmp_path>`
3. Создать минимальный `nginx.conf` (events + http + resolver + include)
4. `docker run --rm -v <overlay_dir>:/etc/nginx/conf.d:ro nginx:alpine nginx -t`
5. Assert exit code 0

**Edge cases:**
- Docker недоступен → skip (не fail)
- `my-cool-app` → nginx -t PASS (проверка нормализации дефисов)
- `independent.com` → personal cert path (не wildcard)

## 4. Common pitfalls

### ⚠️ TRAP[BUG] · 2026-07-20 · P0 · Дефисы в upstream именах
**· Root:** `$upstream_${project_name}` с `my-cool-app` → nginx syntax error
**· Fix:** Нормализация через `nginx_safe_name="${project_name//-/_}"` в `generate_vhost_body()`
**· Prevention:** Все upstream-переменные проходят через `nginx_safe_name`

### ⚠️ TRAP[BUG] · 2026-07-20 · P0 · `head -1` не видит GENERATED маркер
**· Root:** `generated_header()` выводит 2 строки, `head -1` читает только первую (`# ===...`)
**· Fix:** Заменить `head -1 | grep` на `grep -q "GENERATED by add-vhost.sh" "$gen_file"`
**· Prevention:** Не использовать `head -N` для детекции маркера — grep без head надёжнее

### ⚠️ TRAP[DECISION] · 2026-07-20 · — · proxy_pass через переменную
**· Rejected:** Статический hostname в `proxy_pass http://app:8080`
**· Reason:** Статический hostname кэшируется при старте nginx; при перезапуске контейнера (новый IP) — 502/503
**· Rev:** Если nginx перейдёт на динамическую резолюцию через `zone` directive — пересмотреть

### ⚠️ TRAP[DECISION] · 2026-07-20 · — · `http2 on;` vs `listen ... http2`
**· Rejected:** `listen 443 ssl http2;` (современный синтаксис)
**· Reason:** Несовместимость с nginx:alpine < 1.25.1 · В production образе используется `http2 on;` как отдельная директива
**· Rev:** Когда минимальная версия nginx на VPS ≥ 1.25.1 — можно перейти на `listen ... http2`

## 6. Template Syntax Contract (DRIFT-C8)

Два типа `.template` файлов в nginx-модуле:

| Директория | Синтаксис | Рендерер | Когда применяется |
|-----------|-----------|----------|-------------------|
| `config/*.conf.template` | `${PLATFORM_DOMAIN}` | nginx Docker entrypoint (container-internal envsubst script) | При старте nginx-контейнера |
| `templates/*.conf.template` | `{{PLATFORM_DOMAIN}}` | `template_engine.py` | При рендере шаблонов через `make templates-render` |

**Правило:** Никогда не смешивать `${}` и `{{}}` в одном файле.
Каждая директория использует СТРОГО свой синтаксис.

**CI gate:** `test_template_syntax_gate.py` проверяет, что:
- Файлы в `config/` НЕ содержат `{{`
- Файлы в `templates/` НЕ содержат `${`
- Исключение: nginx-переменные вида `${host}`, `${request_uri}` в `config/` разрешены
